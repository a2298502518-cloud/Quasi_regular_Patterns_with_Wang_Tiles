## 1. 本轮决策经过

首轮等权模型只能明确展示同族变体、疏密和细节。本轮先增加方向权重与载波旋转，
观察到团簇向拉长单元、条带的连续变化。但强偏置容易趋近普通条纹，所以继续加入
第二组方向的混合，而不是就此将条纹变化当成充分的多样风格。

第二轮得到交叉连接的单元结构，故保留这一项，并继续做实际试调入口。
所有案例固定 Wang 配置与同一色带；没有逐图归一化，也没有换色制造“风格差异”。

原实现并非必须正确或不可更改。本轮已修改“每个方向等幅”的原假设，明确记录其收益
和对称性代价。另纠正了旧 README 中“瓦片差异仅来自标签”的描述：QRP 还依赖全局坐标，
所以相同标签签名不是可任意搬移的相同图片瓦片。当前仍采用程序化连续场铺砌，
不将它混同为可复用图片瓦片库。

## 2. 数学与实现

权威公式见 [模型说明 §5.1](content-constrained-wang-model.md#51-面向风格控制的方向权重扩展)。
简要而言，用两组非负、各自归一化的方向权重作凸混合，再旋转整个 QRP 载波方向集合。

新增 QRP 参数：

| 参数 | 实现字段 | 用途 |
| --- | --- | --- |
| 方向性 eta | `directionalBias` | 从等权方向到单方向偏重 |
| 结构旋转 alpha | `orientationRadians` | 连续旋转载波集合，不靠重新挑离散方向伪装任意旋转 |
| 交叉混合 t | `crossMix` | 从单方向偏重到第二组方向参与 |

非负幅度之和为 1，所以 `|C|<=1`；权重在空间中为常数，原 Wang C¹ 衔接与层级范围推导
继续成立。零偏置、零旋转恢复原模型；新增方向常量在对象构造时缓存。
预览、研究小样、导出都调用同一 C++ 实现，Python 只调度程序，HTML 只收集参数和显示图片。

必须保留的限制：

- 非等权会改变原 canonical 模型的对称性，不声称原有旋转对称性仍完整保留。
- 很强偏置接近单方向条纹；复杂或非重复的观感不能替代严格非周期性证明。
- 方向性也会改变幅度分布，不是单纯拉伸。D01–D04 的粗场标准差约为
  `0.272865、0.324160、0.463208、0.653698`。
- 旋转的是粗 QRP 载波，Wang 网格及中细层不旋转，因此不等同于刚性旋转整张成图。
- “交叉”是方向混合的视觉提示，不是直角网格、交织拓扑或真实编织遮挡。
- 目前仍是有限 20×20 窗口；内部 C¹ 不代表输出外边界周期匹配。

## 3. 对照小样

目录：`output/qrp-direction-study/`。全部为 640×640 原图，粗场/分层场灰度使用相同的
固定 `[-1,1]` 映射；着色仍为 MidnightGold。

| 组别 | 目的 |
| --- | --- |
| D01–D04 | 偏置 `0、1、3、8`，其余参数一致 |
| D05–D08 | 偏置 3，旋转 `15°、30°、60°、90°` |
| D09–D12 | 相对 D03 分别改变疏密、细节或相位 |
| D13–D16 | 相对 D03 加入交叉混合 `0.15、0.35、0.5`，末组再旋转 45° |

`manifest.json` 保存全部参数与采样统计。排版脚本生成三个 16 图对照板、一个三层阅读板，
以及 `board_candidates.png` 四个起点的简明展示。

视觉观察：D01 以团簇/环状单元为主；D02 单元拉长并沿方向连接；D03 出现明确带状结构；
D15–D16 转为双向参与的连接单元。灰度中已存在这些差异，因此不只是配色效果。
这说明新增控制有实际结构作用，但没有证明形成了四个独立风格类别，更没有完成商业用户验证。

## 4. 本地试调台

入口与启动命令见 README 的“本地试调台”。界面只提供 QRP 控制，Wang 作为内部铺砌机制。
四个起点对应 D01、D02、D06、D16，而不是四套互不相关的生成器。

工作流程：选择起点 → 调整草稿 → 应用生成 → 灰度/着色检查 → 固定图片对比 → 保存参数或导出。
单图 CLI 为：

```text
qrp_wang_qrp_experiment --render directory pixels/tile q frequency A B medium fine bias angle cross
```

预览每瓦片 32 像素（640px）；导出每瓦片 80 像素（1600px）。
同一画布范围重新采样，不是把小图插值放大。拖动只更新草稿，显式应用才计算；
切换三种观察视图不重新计算。缓存包含完整参数、分辨率和可执行文件 SHA-256。

参数 JSON 标记 `qrp-recipe / version=1 / model=directional-qrp-v1`，只保存用户 QRP 参数，
另记录引擎哈希用于追溯。它不是通用项目格式；跨模型版本不保证像素相同。
保存与下载都针对当前已应用图，导入只填入草稿；未应用时禁止直接按新草稿导出。

当前 UI 范围是经过观察的可用探索范围，不是参数空间的全量证明：q 只开放 5/7/9/11/15，
交叉为 0–0.5，方向性为 0–8；中细层强度仍遵守原范围约束。
服务只监听 `127.0.0.1`，无第三方服务、账号或新增 Python 包依赖。

## 5. 验证结果

- Release 构建与现有五个 CTest 通过；只在现有参数化场测试内补充必要语义检查。
- 零扩展时七张旧基准图 SHA-256 全部一致。这证明兼容性，不等于证明旧路线适合所有设计目标。
- 四个 UI 预设经服务调用生成的 640px PNG，与相应研究小样 SHA-256 全部一致。
- 浏览器检查了页面排版、预设切换、固定图对比，以及修改旋转后“未应用”状态。
- 浏览器中完成 1600px 输出并确认结果更新；本机一次实际用时 3.456 秒，不作为跨设备性能保证。
- 保存参数的服务端往返重现、输出尺寸及场值范围按必要检查验证。
- 文件选择器的跨浏览器兼容性、长时间压力、GPU 和周期导出不在本轮验证范围。

## 6. 下一判断点

现在已有可以实际操作、保存并重现的版本，下一步不能仅靠继续自动枚举参数判断“满意”。
需要用户或老师评价：这几个起点及其过渡是否达到期望的结构跨度，哪些值得作为主方向，
哪些仍显得同质。

若结构跨度认可，下一阶段优先用一个实际设计任务检验易用性与可交付性；若仍不足，
应根据具体缺失的视觉目标再调整 QRP 表达，不把参数数量增加当成进展。
原 Word 报告仍对应旧固定实验，尚未改成新模型报告。
