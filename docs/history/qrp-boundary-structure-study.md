# 共享 Wang 接口的 QRP 边界结构代价

日期：2026-09-25。状态：对已保存覆盖库的诊断，不是新生成方法；不修改三组设计或原内容库。

## 1. 结论与范围

[内容覆盖实验](qrp-content-coverage-study.md)扩大了库内局部内容的差异，但接边附近的形态变化不能只用全域 RMSE 解释。
本轮发现：**对当前源池，先截取 16 个区域，再分配给预设的每方向 4 个共享接口，存在无法仅靠排列消除的边界结构冲突。**
这要求重新研究源内容与接口的共同构造，不是继续把网格加密或优化排列当作完整答案。

这一结论不否定 QRP 与 Wang 的结合，也不意味着现有图案不好看。共享边改变局部形态可能产生可接受的设计；
本轮测量的是对源结构的保留代价，不是审美分数、二维拓扑证书或商业价值。
没有证明所有 16 类型目录都不够用，也没有证明增加标签就是正确方案。

输入为 `output/qrp-content-coverage-study/` 的清单及已保存系数库：q=5/8/12，分别保留青金叠瓣、靛蓝细描、铜金镶边。
源位置、源谱、类型分配、28×28 Hermite 网格、H¹ 权重、色带高度、线描高度与配色均不变。
本轮仅比较顺序分配和匹配分配，不混入目标不同的原同区域基线，也不重新优化源块排列。

增加一个对照：相同网格和目标函数，但 16 个源块各自独立拟合，不共享边或角自由度。
这不是合法 Wang 内容库，仅用于区分表示误差与共享约束的代价。误差均在每块 96×96 个点测量；
共享库误差从实际读取的系数重新计算，不直接沿用上一轮误差表。

## 3. 两种不同的必要变化下界

### 固定分配时：同一标签不能保留不同穿越计数

沿边的正轴参数为 s∈[0,1]。对实际色带分界高度或线描中心高度 h，统计相邻采样点的 `(f(s)>h)` 布尔值变化次数，记为 n(h)。
q=5、8 各取 8 个高度，q=12 取 6 个；q=8 包含强调线高度。窄线的中心高度不是窄色带的全部边界。
每条边用 16,385 个点，源边和共享边在 8,193 点下计数相同。
这是采样稳定性核对，不排除采样间的极近成对根、相切或临界高度问题。

每个方向每个标签包含 8 个边槽。共享值曲线在同一高度只有一个计数，因此至少要改变

\[
B_{\Gamma,h}=8-\max_k\#\{e\in\Gamma:n_e(h)=k\}
\]

个边槽的该项计数。将它对组和高度求和，得到固定分配的下界；不保证存在一条曲线同时达到各项下界。

| q | 边槽×高度总数 | 必要变化下界：顺序→匹配 | 当前拟合实际变化：顺序→匹配 |
| --- | ---: | ---: | ---: |
| 5 | 512 | 212 → 176 | 335 → 272 |
| 8 | 512 | 229 → 239 | 311 → 295 |
| 12 | 384 | 198 → 199 | 275 → 268 |

单位是“一个源边槽在一个高度上的计数是否改变”，不是改变面积、丢失图元数或坏像素比例。
匹配分配降低了三组实际变化项数，也降低了场误差；但 q=8/12 的必要变化下界反而略升。
因此，上一轮按值和梯度优化的分配并没有一致减少这种结构冲突；不能声称实际结果全部变差。

### 任意分配时：接口数量限制可保留的计数向量

把同一条边在所有选定高度上的计数组成向量 σ(e)。每方向共有 32 个源边槽，只有 4 条共享边曲线。
一个共享边曲线至多与一种 σ 完全一致。因此，无论怎样重新排列源块，保持原计数向量的边槽至多来自 4 种 σ。

设计数向量的出现频数由大到小为 a₁,a₂,…，则有宽松下界

\[
B_{\rm any}=32-\sum_{i=1}^{\min(4,K)}a_i.
\]

这里忽略每标签的 8 槽容量以及四边/角点的耦合，故只给出必要条件，不是可实现最优值。
不能对每个 aᵢ直接截断为 8：同一种向量可能由多个标签承载。

| q | 原始横边 / 竖边的不同计数向量数 | 每方向共享接口数 | 任意分配至少改变的完整向量：横 / 竖 |
| --- | ---: | ---: | ---: |
| 5 | 16 / 14 | 4 | 20 / 32、16 / 32 |
| 8 | 16 / 16 | 4 | 20 / 32、20 / 32 |
| 12 | 16 / 16 | 4 | 20 / 32、20 / 32 |

固定源池中不同 σ 的数量不会因排列改变。更彻底地搜索 16! 个排列，也不能消除这一必要冲突。
此处仅共享值曲线就足以产生限制，并不依赖 C¹；但它没有量化把 C¹ 放宽到 C⁰ 能减少多少实际形变。
计数相同仍不保证交点位置、轮廓连接方式或二维拓扑相同，故也不能据此把 14–16 个标签当成充分条件。

## 4. 放大图与边曲线证据

输出 `boundary_details.png`：每组在既定 4×4 布局 wide_A 的 24 个邻接中，选择中心半块宽高窗口里标量改动 RMSE 最大的一处。
这是按统一规则选择的诊断最坏例，不能冒充平均视觉效果。图中横接边标“下 / 上”，竖接边标“左 / 右”；红色短标位于图框外。
局部窗口重新数值采样，保持原显示配方与 2×2 超采样，不对 PNG 做锐化或补缝。

左列是尚有接缝的原始源块，不是可直接替代右列的理想答案。右列是现有合法共享拟合。
q=5 可见色带连接改变，q=8 可见接边附近的小闭合形状与墨色区域变化，q=12 可见局部闭合区域和色带改形。
这些是视觉观察，没有据此声称已严格计数二维图元的出生、消失或合并。

输出 `edge_trace_conflicts.png`：灰线是同标签的 8 条源边值曲线，橙线是共享拟合边，蓝线是所选实际显示高度。
例如 q=5 的竖边标签 1 在高度 0.22 上，源边计数为 `[2,2,2,10,4,4,8,8]`，拟合后均为 0。
这说明该高度的边界穿越被消除，不表示整块纹样的对应轮廓全部消失。
拟合是有内部与梯度耦合的 H¹ 投影，不能把橙线简单称为这些值曲线的算术平均。

## 5. 下一步的方法性调整

现在需要审视的是“先固定任意源块，再让少量预设接口接纳它们”的建库顺序。
下一候选应共同设计 **QRP 源内容、边界曲线族和 Wang 可铺目录**，而不把当前二值角点目录当作不可改动的前提。
这仍以离线固定内容、同标签保证实际衔接、不同合法布局纯复用为底线；不是退回依赖实例位置的大图切块。

下一步先在 q=8 线描设计上推导并验证这个共同构造，因为其细线使边界形态变化容易观察：

1. 把源块选择/构造与接口关系共同列为未知量，明确边曲线、角点及合法目录的兼容条件；不要只在现有 H¹ 目标里加一个未经分析的罚项。
2. 尽量先在相同 16 类型预算下比较；若目录或预算必须变化，应单列变量，不能把更多类型带来的收益算给新方法。
3. 同时检查局部结构改动、库内内容差异和 QRP 参数响应，避免只挑容易接边但高度同质的源块。
4. 以相同显示给出原方法/候选方法的实际纹样与多个合法重铺，不把穿越计数优化直接等同于好看。

这里尚未实现新的共同构造，也未证明其可行或优越。穿越计数是本轮诊断工具，不应直接固化为依赖某套配色的 QRP 定义。
相位变化可能改变计数向量；不能每次参数变化就离散重排标签，再沿用之前的连续响应结论。
用户控制仍在 QRP 层，Wang 的内部类型/接口设计不成为新的用户调参项。

## 6. 实现、验证与生命周期

唯一新增代码入口为 `tools/inspect_tile_structure.py`。它读取既有库，共用 `joint_field.py` 的源求值、拟合、误差和显示，
共用 `board_common.py` 的图板字体；没有新生产分支或第二套数学实现。它保留为可复现的只读输入诊断，不进入默认 C++ 构建。
输出 JSON 记录源清单与每份系数库的 SHA-256，以及计数、分组、独立对照、裁图选择信息。

必要核对：三组独立拟合；六套顺序/匹配库的计数采样稳定性；每个标签组完整值与一阶梯度一致；
裁图坐标方向核对；数值图板视觉检查；Python 语法与 Git diff 格式检查。
生产 C++、共同求解器和已有库均未修改，因此不重复全量构建或扩大测试体系。
按工程审阅技能做实现者自审，不声称独立评审；未提交、未推送。

```powershell
# 需先生成内容覆盖库，参见上一轮记录
python -X utf8 tools/inspect_tile_structure.py
# 自定义位置
python -X utf8 tools/inspect_tile_structure.py --source output/coverage --output output/boundary-structure
```

默认输出为 `output/qrp-boundary-structure-study/`：`results.json`、`boundary_details.png`、`edge_trace_conflicts.png`。
