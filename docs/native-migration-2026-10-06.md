# 2026-10-06 当前方法迁入 C++ / OpenGL

用户明确最终工程使用 C++ 与 OpenGL，并授权开始迁移。本轮不恢复旧算法、不改论文公式、不重新选图。
旧桌面及其旧数值后台仍在删除区；只复用第三方窗口/界面技术，不把旧类型库与拟合器接回主线。
采用研究图形工程 skill 核对数学与坐标，按 C++ 简化 skill 收敛职责，收尾为实现者自审；没有委派独立评审。

## 实际分工

| 实现 | 唯一职责 |
| --- | --- |
| `src/qrp/Field.*` | QRP 波矢/场值及梯度、源区域探针、圆分关系、Householder QR / nearest-plane、有限相位场、尺寸界、边标签和合法布局 |
| `src/render/Raster.*` | 像素中心坐标、2×2 线性光超采样、固定高度分色、RGB8 PNG / 参数元数据 |
| `apps/export_main.cpp` | C++ 参数命令行编排与三张图输出，不定义第二套算法 |
| `apps/desktop/main.cpp` | 草稿/已应用状态、后台作业、GL 纹理生命周期、ImGui 控件和预览/导出调度 |
| `tools/qrp_*.py` / `wang_qrp.py` 等 | 冻结数值参考及已有科研证据复现，不是正式程序的进程后台 |

数学核心没有 GL、UI 或 JSON 依赖。桌面只是表达用户意图；C++ 数学对象拥有源、保护区、连接常量和布局规则。
渲染消费不可变快照；纹理只在新结果完成后上传，重绘、悬停、缩放不会重新求场。
参数更改保留在草稿中，Apply 才生成。改变配色、画幅、布局或导出分辨率时复用已有解析 Atlas；改变源或选区时才重新准备。

当前阶段场求值仍在 CPU C++ 中多线程执行，OpenGL 3.3 负责纹理显示和 ImGui 绘制。
这是完整的原生运行链路，不是 C++ 窗口调用 Python 生成 PNG；也不宣称已经实现 GPU 场求值。
预览和高清使用同一 Raster，导出从公式重新高分辨率采样，不截取窗口或放大预览。
运行时的少量瓦片像素缓存只覆盖实际布局使用的角色，没有参数专属的磁盘图像建库。

## 保持的数学与显示语义

- 索引 `m=1..floor(Q)`、按项数归一化；非整数 Q 仍使用原公式，三次方向仍是方向分量立方。
- 基础族按浮点 Q 的精确有理分子处理认证关系，三次族用单位矩阵；不是逐 Q 白名单。
- 使用与 NumPy/LAPACK 相同取号约定的 Householder QR 与 ties-to-even nearest-plane，未换成其他求支器。
- 保留探针对正负源偏移平均的诊断场，最终源仍使用正偏移，二者不混用。
- 同一角色的相位只依赖类型及局部坐标，目录为 16WH；W/H 按原充分界和面积枚举选择。
- 布局 y 向上、图像行向下；源画幅以原点为中心，Wang 画幅沿用原裁切位置。
- 阈值等号侧与参考一致，先分色再在线性光中超采样，最终编码为 sRGB8。

## 启动与操作

```powershell
./tools/native.ps1 -Action run
./tools/native.ps1 -Action test
./build/Release/qrp_generate.exe --q 7 --extent 24 --pixels 64 --output output/my-native
```

VSCode F5 选择 **QRP C++ / OpenGL 操作台**，自动构建 Debug；运行任务 **QRP: run native workbench** 使用 Release。
核心源参数为 Q、函数族、频率、源偏移及源区域。W/H、相位支和内部状态不暴露成风格滑块。
布局种子与全同状态在独立对照面板，配色为显示控制，不冒称改变了源。
GUI 每次保存到新的 `output/native-workbench/<时间戳>/`，保存 `wang.png`、`source.png`、`parameters.json`。
默认 24×24 单位、48px/单位预览；高清默认 192px/单位即 4608×4608，保存已应用的参数而非未提交草稿。

构建依赖为锁定版本的 GLFW、ImGui、nlohmann JSON、lodepng。新机器通过 FetchContent 获取。
本机 `.codex-temp/native-deps/` 是独立的第三方源码缓存，不引用删除区，也没有复制旧工程的 CMakeCache。
实现结束时工作区仍包含前两轮清理等未提交变更，未还原或覆盖这些变化；
实现阶段未暂存、提交或推送，后续版本保存按用户的明确请求执行。

## 核验事实

Release 与 Debug 构建通过；原生 CTest 包含 Q5.5、Q4.8 三次方向、Q7 非零偏移的必要检查。
完整目录边迹、核心、解析界、梯度和扩幅通过，未重新维护旧方法的测试。

8 组输入与冻结 Python 对照：自动区域的 Q4.8 三次方向和 Q5.5/6/7/8/12 基础方向，
外加 Q7 偏移 `(0.3,0.2)` 的显式区域和自动区域。
探针、关系矩阵、整数提升、连接尺寸、解析界、布局一致，24 张 288×288 图的 RGB 像素完全一致；
采样场值/梯度最大差异约 1.64e−13。
另外只生成 Q7 的纯源/A/B 三张 4608×4608，RGB 像素均与已有交付一致；未覆盖或重输出原 30 张交付。
对照脚本可用 `tests/compare_native.py --hd` 复现，新数据位于 `output/native-migration-check/`。

实际 OpenGL smoke 在本机 Intel RaptorLake-S Mobile Graphics 的 OpenGL 3.3 上通过，
包括独立 C++ 生成、两张纹理上传、中文 ImGui 绘制、隐藏窗口截图和保存预览。
截图为 `output/native-migration-check/原生操作台.png`，非 UI mockup。

一次 Release 测量：默认 Q7 准备约 0.029s，1152×1152 的 Wang 与纯源两张图约 0.092s；
另一次 Q7 三张 4608×4608（含 PNG 编码）约 6.1s。不是严格性能基准，不与 Python 的不同工作量直接作倍数比较。

Debug 初次 smoke 曾超过 60s。排查到每个子像素的阈值查找和像素复制都创建了 Debug STL 容器迭代器，
多线程反复注册迭代器造成很高的开销。将这两个热点改为等价的索引二分和已分配缓冲区指针，
保留所有其他 Debug 检查、数学公式、阈值等号侧和内存所有权，没有关闭全工程的迭代器检查。
修改后 Debug smoke 通过，默认两张图的出图时间一次测量约 0.33s，准备约 0.07s；
再次运行完整迁移对照及一组高清对照，像素仍一致。

高清检查曾因 PNG 库默认自动转换为索引色，且临时比较未统一 RGB，误报三张不等。
按系统排错 skill 核对参数、模式和像素后定位为格式/比较问题，没有更改数学公式；
现将 PNG 明确固定为 RGB8、sRGB intent 0、300 DPI，比较读取也统一 RGB。
文件压缩和旧 ICC 元数据不同，因此不要求新旧文件 SHA-256 相同。

## 尚未扩大承诺的部分

这是一版可以运行和调参的本地原生实现，不是完整交互产品验收。
鼠标拖拽、滚轮缩放、多次草稿/Apply/高清按钮等完整交互仍需人工使用确认；已核对代码状态流，但不称为鼠标测试。
没有实现 GPU 相位场、任意非线性 QRP、连续跨分支无跳变、风格自动推荐、参数文件导入或批量图库界面。
这些不是当前迁移正确性的前置条件，不为它们继续无限扩展本轮。

数学域仍是有限 Q≥1，但当前矩阵预算为 2048 项，图像单边为 16384px，尺寸方形枚举见证上限为 10000。
64 位整数提升和浮点关系容差超限会报错；理论存在性不等于所有有限输入都能在机器预算内计算。
自动探针遇到 Q1 等没有二维峰的源会要求显式区域，不伪造母题。
没有新增理论、美学或商业价值结论。下一步应先由用户实际调参验收，再决定是否需要 GPU 或交互优化。
